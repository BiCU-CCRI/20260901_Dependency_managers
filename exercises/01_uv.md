# Exercise 1: uv, a fast all-in-one Python manager

`uv` replaces pip, virtualenv, pyenv, and pip-tools with one fast tool. In this
exercise you will create a project, add a dependency, run code without
activating anything, and see the lockfile that makes it reproducible.

Rough time: 8 minutes.

## 1. Install uv

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"   # make uv available in this shell
uv --version
```

Why the `source` line: the installer adds `uv` to `~/.local/bin`. Sourcing the
env file (or opening a new terminal) puts it on your `PATH` now. Expected: a
version string like `uv 0.11.x` or newer.

## 2. Create a project

```bash
cd /tmp
uv init demo-uv
cd demo-uv
ls -a
```

`uv init` creates a `pyproject.toml` (the project manifest), a `.python-version`
file, and a starter `main.py`. Nothing is installed yet, and no environment is
activated.

## 3. Add a dependency

```bash
uv add "polars>=1.0"
```

This does several things at once: it selects and downloads a Python
interpreter if needed, creates a `.venv` in the project, resolves and installs
`polars` plus its dependencies, records the requirement in `pyproject.toml`, and
writes the exact resolved versions to `uv.lock`.

Look at what changed:

```bash
cat pyproject.toml
head -n 20 uv.lock
```

The `uv.lock` file pins every package, including transitive ones. That is the
piece plain `pip` does not give you.

## 4. Run code without activating anything

```bash
uv run python -c "import polars as pl; print(pl.__version__)"
```

`uv run` ensures the environment matches the lockfile, then runs the command
inside it. You never typed `source .venv/bin/activate`. Expected: the polars
version prints.

## 5. Reproduce the environment from the lockfile

This is what a colleague would do after cloning your project:

```bash
rm -rf .venv
uv sync
uv run python -c "import polars; print('rebuilt from uv.lock')"
```

`uv sync` rebuilds `.venv` to exactly match `uv.lock`. Same versions, every
machine.

## 6. Bonus: run a CLI tool without installing it

```bash
uvx ruff --version
```

`uvx` (short for `uv tool run`) fetches and runs a Python CLI tool in a
throwaway environment. This is the same job `pipx run` does, covered later.

## Takeaways

- One tool for Python versions, environments, dependencies, and CLI tools.
- `uv add` and `uv sync` keep `pyproject.toml` and `uv.lock` in sync for you.
- `uv run` removes the activate step entirely.
- Limitation: PyPI and Python only. For `samtools` or `bwa`, use `pixi` next.

Commit `pyproject.toml`, `uv.lock`, and `.python-version` to git. Do not commit
`.venv`.
