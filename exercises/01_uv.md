# Exercise 1: uv, a fast all-in-one Python manager

`uv` replaces pip, virtualenv, pyenv, and pip-tools with one fast tool. In this
exercise you will create a project, add a dependency, run code without
activating anything, and see the lockfile that makes it reproducible.

## 1. Install uv

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
uv --version
```

Expected: a version string like `uv 0.12.8 (x86_64-unknown-linux-musl)` or newer.

> [!IMPORTANT]
> For a long-lived CI or archival workflow, pin the uv version rather than
> installing whatever happens to be latest. The floating installer is used here
> to keep the live exercise short.

## 2. Create a project

```bash
cd /tmp
uv init demo-uv
cd demo-uv
ls -a
```

`uv init` creates a `pyproject.toml` (the project manifest), and a `.python-version`
file. Nothing is installed yet, and no environment is activated.

For stronger interpreter reproducibility, pin an exact Python patch release
rather than only a minor series.

Check the system-wide Python version before we pin anything in the environment:

```bash
which python
python --version
```

Pin a specific Python version -  on purpose a different one than the system version:

```bash
uv python pin 3.14.1
```

> [!NOTE]
> A request such as `3.14` allows any compatible 3.14 patch release; `3.14.1` is
> an exact interpreter version.

Check the project Python version:

```bash
uv run which python
uv run python --version
```

## 3. Add a dependency

```bash
uv add "polars>=1.0"
```

This does several things at once: it selects and downloads a Python
interpreter if needed, creates a `.venv` in the project, resolves and installs
`polars` plus its dependencies, records the requirement in `pyproject.toml`, and
writes the resolved dependency graph to `uv.lock`.

Look at what changed:

```bash
cat pyproject.toml
head -n 20 uv.lock
```

The `uv.lock` file records direct and transitive dependencies as a universal
project lock. This is different from `pip freeze`, which snapshots an already
installed environment. Recent pip versions also have an experimental
`pip lock` command, but uv makes locking part of the normal project workflow.

## 4. Run code without activating anything

```bash
uv run python -c "import polars as pl; print(pl.__version__)"
```

`uv run` ensures the environment matches the lockfile, then runs the command
inside it. You never typed `source .venv/bin/activate`. Expected: the polars
version prints.

Running the same command using the system-wide Python installation will fail:

```bash
python -c "import polars as pl; print(pl.__version__)"
```

## 5. Reproduce the environment from the lockfile

This is what a colleague would do after cloning your project:

```bash
rm -rf .venv
# uv sync --locked # Not necessary as uv automatically rebuilds the environment from the lock file but more explicit
uv run --locked python -c "import sys; import polars as pl; print('rebuilt from uv.lock'); print(sys.version); print(pl.__version__)"
```

`--locked` makes the command fail if `pyproject.toml` and `uv.lock` disagree,
instead of silently updating the lock. On supported platforms and Python
versions, the project is rebuilt from the same locked resolution, although the
actual wheel or artifact can still differ by platform.

## 6. Bonus: run a CLI tool without installing it

```bash
uvx ruff --version
```

`uvx` (short for `uv tool run`) fetches and runs a Python CLI tool in an
isolated (~throwaway) tool environment. This is the same job `pipx run` does, covered later.
Because this tool environment is outside the project lock, use a project
dependency instead when the exact tool version affects research results.

## 7. Bonus: build a Python package from source

By default, uv prefers a prebuilt wheel when one is available. Force `tomli`, a
small pure-Python package, to install from its source distribution (sdist):

```bash
uv add --no-binary-package tomli "tomli==2.0.1"
```

uv downloads the `.tar.gz` source archive, builds a wheel locally in its cache,
and installs that wheel into `.venv`. Confirm that it is available:

```bash
uv run python -c "import tomli; print(tomli.__version__)"
```

`uv.lock` records the source distribution used to reproduce the resolution.
Locate the `tomli` entry and inspect its `sdist` field:

```bash
grep -A 12 '^name = "tomli"' uv.lock
```

The `sdist` entry contains the archive URL and content hash. uv may also list
prebuilt wheels in the same lock entry; `--no-binary-package` controls this
installation, while the lockfile records all compatible artifacts that uv
resolved.

## Takeaways

- One tool for Python versions, environments, dependencies, and CLI tools.
- `uv add` and `uv sync` keep `pyproject.toml` and `uv.lock` in sync for you.
- `uv run` removes the shell-activation step.
- Use `--locked` in CI to detect stale lockfiles rather than re-resolving.
- Limitation: uv manages the Python packaging ecosystem, not arbitrary system
  packages such as `samtools` or `bwa`. For those, use `pixi` next.

Commit `pyproject.toml`, `uv.lock`, and `.python-version` to git. Do not commit
`.venv`.
